# 多语言（i18n）

next-intl 4，`localePrefix: "always"`：所有前台 URL 带 `/en` 或 `/zh` 前缀，根路径按
`Accept-Language` 自动 302。后台 `/admin` 不在 i18n 体系内（纯中文）。

## 文件

| 文件 | 作用 |
|---|---|
| `src/i18n/routing.ts` | locales 定义（加语言在这里） |
| `src/i18n/request.ts` | 按请求加载 messages |
| `src/i18n/navigation.ts` | 带 locale 的 Link/redirect/useRouter |
| `messages/en.json` `zh.json` | 全部静态文案（按页面分组） |
| `src/middleware.ts` | locale 协商；matcher 排除 api/admin/静态文件 |

## 静态文案 vs 数据库内容

- **静态文案**（按钮、标题、表单 label）→ messages JSON，组件内 `useTranslations()` / `getTranslations()`
- **数据库内容**（文章/案例/FAQ/行业）→ 双语字段成对（`titleEn`/`titleZh`），页面内 `locale === "zh" ? x.titleZh : x.titleEn`

## 新增一种语言（如 ja）

1. `routing.ts` 的 `locales` 加 `"ja"`
2. 复制 `messages/en.json` → `messages/ja.json` 翻译
3. 数据库内容：为相关表加 `*Ja` 字段（或迁移到 JSON 列）——工作量大，建议确认商业需求后再做
4. `lib/seo/site.ts` 的 `LOCALES` 同步

## 缺失 key 检测

next-intl 在 dev 模式下对缺失 key 在终端打 warning 并显示 key 本身。
构建期硬检查（可选）：写脚本对比两份 JSON 的扁平 key 集合，CI 中不一致即 fail。

## GEO 文章的翻译

发布时 `publisher.ts` 用 Sonnet 自动把英文稿翻成中文（`bodyZh`）。
MOCK 模式下中文为占位拼接——**配置真实 API key 前发布的文章，中文版需人工复核**。
